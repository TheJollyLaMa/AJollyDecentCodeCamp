Decent Code Camp · prepared course

Turn a useful idea into a Web3 dapp prototype

A beginner-friendly, facilitator-led course that starts with your problem, builds core web skills, and finishes with a tested, documented prototype. No wallet or crypto purchase is required for the lessons.

Status: local course material, not enrollment. The course and Sandbox exercise are prepared in source repositories. No cohort dates, hosted course, payment checkout, or live learner records are active.

What you will practice

  • Turn a real need into a small, testable product brief and explain who controls its data and decisions.
  • Build a responsive web interface with HTML, CSS, JavaScript, and beginner Python practice.
  • Use Git, tests, APIs, and a wallet/contract simulation to understand a dapp's parts and limits.
  • Use AI coding tools as optional collaborators: ask bounded questions, inspect generated changes, run tests, and keep the final decisions yours.
  • Present a working prototype and evidence you choose to share. A blockchain deployment is not part of this pilot.

12-week learning path

  1. 1 · Need and idea

    Outcome: Map a user need, assumptions, and who should retain agency.

    Exercise: Write a one-page product brief and compare it with a no-build alternative.

    Evidence: One-page product brief and a no-build alternative.

  2. 2 · HTML and accessibility

    Outcome: Structure a page with headings, labels, links, and keyboard navigation.

    Exercise: Build the brief's first screen and test it using only a keyboard.

    Evidence: A semantic page and accessibility checklist.

  3. 3 · CSS and responsive design

    Outcome: Style a small interface for narrow and wide screens.

    Exercise: Add a small design system and test mobile and desktop widths.

    Evidence: Two viewport screenshots, with private details removed.

  4. 4 · JavaScript and interaction

    Outcome: Model one user action, validation rule, and honest error state.

    Exercise: Add an interaction and test empty, valid, and invalid input.

    Evidence: A working interaction and a test case.

  5. 5 · Python foundations

    Outcome: Practice input, types, conditions, loops, and functions using existing camp examples.

    Exercise: Adapt a Python practice problem using fictional input.

    Evidence: One adapted exercise with sample input/output.

  6. 6 · Git and review

    Outcome: Make small commits, explain a change, and review code with permission.

    Exercise: Create a branch, inspect a diff, and run a test.

    Evidence: A change log and a test run.

  7. 7 · Data and APIs

    Outcome: Read sample API data, handle unavailable states, and avoid sending private data.

    Exercise: Read a public sample or local fixture and handle an empty response.

    Evidence: A data-flow sketch and loading/error states.

  8. 8 · Dapp boundaries

    Outcome: Compare a normal web app with a wallet, signature, and contract; identify risks and non-chain alternatives.

    Exercise: Draw the browser, optional wallet, mock contract, and event/read model.

    Evidence: A simple architecture diagram and a privacy checklist.

  9. 9 · Wallet interaction (mock)

    Outcome: Explain connect/reject/disconnect and unsupported states without opening a wallet.

    Exercise: Build a four-state mock flow that never implies a live connection.

    Evidence: A UI state table for each outcome.

  10. 10 · Events and ledger exercise

    Outcome: Distinguish a local event-shaped record from a confirmed on-chain event.

    Exercise: Use the Sandbox synthetic facilitator/learner ledger and inspect its bounds and unavailable state.

    Evidence: A local test record and a short explanation of what is not on-chain.

  11. 11 · Prototype and testing

    Outcome: Connect a prototype to a mock contract adapter and test success, rejection, and unavailable states.

    Exercise: Add tests for a simulated call, rejection, and missing provider without real signatures.

    Evidence: A demo script and passing local tests.

  12. 12 · Demo and next steps

    Outcome: Present a prototype, its trade-offs, and what real deployment would require.

    Exercise: Give a short demo and list the independent review and deployment gates.

    Evidence: An optional public portfolio entry or a private/local equivalent.
